## 3. What the run establishes

- **One memory per profile.** Session A in `workspace-a` posts a note; session B in `workspace-b`
  (different cwd) makes no tool call and still receives that note in its committed pulse
  `<confluence-memory scope="global" …>`. C's board call sees A's note **and** the seeded legacy
  note; D reads A's note body; E recalls a literal phrase spoken in A's session from the other
  directory.
- **Global store, legacy untouched.** New writes land only under
  `<run>/dsh-home/storages/confluence/v1/workspaces/ws_0000000000000000/`. The seeded legacy
  workspace `ws_1a2b3c4d5e6f7081` is merged read-only: its files are byte-identical afterwards and
  nothing was migrated.
- **Watermarks and cold start.** `boardReadSeq` advances after the board/read sessions while the
  post-only/pulse-only sessions keep it `null`; the writer's first request headers already carry all
  six Confluence tools and the pulse, so the cold-start activation race is closed.
- **The real profile was not touched.** The pre-existing real `~/.dsh` store (15 files) contains no
  trace of the run (note title / run stamp), and no scratch profile leaked into the real home.
- **No workspace key is passed anywhere.** `E2E-10` checks every Confluence tool call for a
  `workspace`/`ws`/`scope` argument or a `ws_<16hex>` literal.

## 4. Three product bugs found by the initial run (fixed before the re-run)

1. **`parseThroughMarker` only accepted the last line.** The tool renderer appends the `through=`
   marker followed by closing tag lines, so the marker was never the last line and `boardReadSeq`
   never advanced. Fix: scan every rendered line and take the last valid marker
   (`lib/watermark.js:182`). Found by E2E-11.
2. **Cold-start activation raced the first request.** Tools, pulse and panel routes were registered
   after the first `await` in `index.js`, so a cold headless session's first request had no
   Confluence tools and no pulse. Fix: register synchronously before the async store/board/watermark
   attach (`index.js:328-366`; see the comment "Tools/pulse/routes are registered synchronously above
   so the first model request after activation already sees the plugin"). Found by E2E-04/E2E-05 and
   the writer header inspection.
3. **`sessionQuery` was captured too early.** The service registered roughly 150 ms after plugin
   construction, so an eager capture made `confluence_recall` permanently unavailable on a cold
   headless boot. Fix: resolve it lazily through `deps.getSessionQuery` on each call
   (`lib/recall.js:283-302`, wired in `index.js:161`). Found by E2E-12.

All three fixes are covered by the re-run: the final evidence above is from the fixed tree.
