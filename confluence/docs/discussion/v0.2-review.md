## 7. Residual risks / open items

1. **PTC preset reachability** (`run_code` bindings) — M0-S3 open, not executed (documented). The six
   tool definitions are preset-independent by design.
2. **Multi-window live freshness** — polling is the contract; no measurement; the pulse cursor churn
   (R-05) makes this slightly more important.
3. **Panel rendering/visual** — not executed (documented); contract/route-level only.
4. **Real desktop-profile install + DSH restart** — not executed; the linked bundle needs a restart to
   load the new Host modules (documented).
5. **Retention vs the ADR "legacy appears in export/pulse" wording** — export excludes entries older than
   `store.retentionDays` (default 90; my run: `skippedRetention=1`, old legacy note absent) and the pulse
   drops entries older than 7 days; the board/panel still show them. Not data loss, but ADR §3 /
   acceptance §2 should say "within retention" or the operator must raise `retentionDays` before a
   historical export.
6. **Cold-start behaviour** — R-03 is a real store-layer race; the E2E still records a warm-up session
   ("absorbs the first-mount activation race", `summary.json` E2E-00d) even though its evidence record
   states the synchronous-registration fix closed that race. Keep a dedicated cold-start test (first
   request already carries all six tools + pulse; concurrent `openGlobal` does not double-open).
7. **Legacy view is static per mount** (`store.js:738-782`) — a still-running v0.1 writer's later appends
   are invisible until the next mount (documented as acceptable).
8. **Go consumer real-fixture proof is stale** (R-08); the v0.1.0 fixture passes, but it does not prove
   v0.2.0 output is consumed unchanged.
9. `docs/discussion/v0.2-review.md` (this file) and the E2E evidence doc are new untracked docs; decide
   whether they ship or stay dev-only (neither is in `package.json` `files`, so they don't ship).
