# Confluence v0.4 — binding interface contract

- Status: **binding** for the v0.4 build round. Every workstream codes against
  this file; deviations go to the Lead before landing.
- Decision: `docs/adr/0009-long-term-memory-persona-style.md` (extends ADR 0008).
- Product: three layers — workspace bus (unchanged) + **long-term memory
  (`pattern`)** + **user persona (`profile`)** + **style cards (`style`,
  two channels)**. All global layers are profile-wide, tagged, portable, and
  injected through bounded prompt blocks.
- Unchanged guarantees: offline (no network/port/subprocess/model call),
  append-only JSONL, bounded prompt text, untrusted content rules, metadata-only
  ledger, `privacy.privateSessions` invisibility.

---

## 1. Records (all in the global scope `ws_0000000000000000`)

`store.js:KNOWN_RECORD_TYPES` becomes
`entry|session|tombstone|context|message|profile|profile-reset|pattern|style|memory-migration`
(three sync points: `KNOWN_RECORD_TYPES`, `isValidKnownRecord`, `dedupeKeyFor`).
All new records are append-only; an update is a new record with the same stable
`key`, so folds are last-write-wins per key.

### 1.1 `pattern` — long-term memory

```js
{
  v: 1, type: 'pattern', id: 'pat_<ULID>', ws: 'ws_0000000000000000',
  key: 'windows.path-rename-retry',        // ^[a-z0-9][a-z0-9._-]{0,63}$
  category: 'workflow'|'project'|'domain'|'pitfall'|'heuristic'|'quality',
  title: '<=120 chars',
  body: '<=2048 bytes',                     // the generalizable pattern itself
  tags: ['windows','fs'],                   // <=8, ^[a-z0-9][a-z0-9_-]{0,31}$
  scope: 'global'|'workspace',              // default global
  workspaceKey?: 'ws_<16hex>', workspaceLabel?: '<=120',
  status: 'candidate'|'active'|'rejected'|'superseded',
  confidence: 0.0..1.0,                     // default 0.5
  source: 'agent'|'user'|'import'|'migration',
  evidence: [{ sessionId?, note? }],        // <=3, metadata only
  author: { sessionId?, title? },
  ts, seq
}
```

Fold: per `key`, the record with the greatest `seq` wins (status included).
Live = `active`; candidates are listed separately and never injected as rules.

### 1.2 `style` — output style card (two channels)

```js
{
  v: 1, type: 'style', id: 'sty_<ULID>', ws: 'ws_0000000000000000',
  channel: 'chat'|'engineering',
  area: 'general'|'tone'|'structure'|'commit'|'comment'|'docs'|'naming'|'error'|'log'|'ui',
  key: 'commit.zh-conventional',             // ^[a-z0-9][a-z0-9._-]{0,63}$
  title: '<=120 chars',
  rule: '<=1024 bytes',
  examples: [{ bad: '<=512 bytes', good: '<=512 bytes' }],   // <=3
  tags: ['commit'],                          // <=8
  priority: 0..100,                          // default 50 (higher first)
  enabled: true,
  confidence: 0..1, source: 'user'|'agent'|'import',
  author: { sessionId?, title? },
  ts, seq
}
```

Fold: per `(channel, key)`, greatest `seq` wins. `enabled:false` = disabled.
`chat` covers tone/structure/general areas; `engineering` covers
commit/comment/docs/naming/error/log/ui.

### 1.3 `profile` — user persona (v0.3 record type, new section set)

Sections: `identity | personality | communication | habits | boundaries | taste`.
Legacy aliases folded at read time: `preferences → communication`,
`rules → boundaries`. Legacy `tech`/`context` facts are **not persona**: they
are migrated once into `pattern` records (§5) and skipped by persona rendering.

### 1.4 `memory-migration`

```js
{ v:1, type:'memory-migration', id:'mig_<ULID>', ws:GLOBAL,
  version: 1, source: 'profile-v03', ts, seq }
```

One marker per applied migration; never repeated.

## 2. Services

### 2.1 `lib/memory.js` (new)

```js
export const PATTERN_CATEGORIES
export const PATTERN_KEY_RE
export function foldPatterns(records)        // {byKey: Map, active:[], candidates:[], counts}
export class MemoryService {
  constructor({ store, config, redactor, logger, deps })
  async attach()                             // open global journal, prime fold, run migration once
  list({ status?, category?, query?, limit? })          // sync
  activeFor(workspaceKey)                    // sync: active patterns relevant to one workspace
  async add({ key?, category, title, body, tags?, scope?, workspaceKey?, workspaceLabel?, confidence?, evidence?, author? })
                                             // -> { key, status:'candidate', seq }  (always candidate)
  async promote({ key, author })             // -> { key, status:'active' }
  async reject({ key, author })              // -> { key, status:'rejected' }
  async update({ key, title?, body?, tags?, confidence?, author }) // -> same key, new seq (keeps status)
  async forget({ key, author })              // -> { key, status:'rejected' }
  pendingCount() / renderBlock({ workspaceKey })        // sync prompt text (§3.2)
}
```

Caps: `memory.maxPatterns` live patterns (candidate+active), body bytes,
title/tags/evidence bounds, `memory.maxInjectPatterns`, `memory.maxInjectChars`.
Migration: if no `memory-migration` marker exists, convert legacy profile
`tech`/`context` facts into `pattern` records (category `project`/`domain`,
source `migration`, key `migrated.<section>.<key>` sanitized), then append the
marker. Idempotent, best effort, never rewrites existing records.

### 2.2 `lib/profile.js` (rework)

`PROFILE_SECTIONS` becomes the six persona sections (legacy alias map exported
for folds). Everything else (LWW fold, reset generations, redaction, caps,
`render()`) keeps its v0.3 mechanics; `render()` renders **persona only** with
the fixed section order `identity, personality, communication, habits,
boundaries, taste`, <=3 facts/section, <=80 chars/value, <=`profile.maxInjectChars`.
Empty persona => `''` (index substitutes the onboarding nudge).

### 2.3 `lib/style.js` (new)

```js
export const STYLE_CHANNELS = ['chat','engineering']
export const STYLE_AREAS
export function foldStyles(records)          // {byChannelKey: Map, active:[], counts}
export class StyleService {
  constructor({ store, config, redactor, logger, deps })
  async attach()                             // open global journal, prime fold
  list({ channel? })                         // sync
  async set({ channel, area, key, title, rule, examples?, tags?, priority?, enabled?, author? })
  async disable({ channel, key, author })    // -> enabled:false record
  renderBlock()                              // sync prompt text (§3.3)
}
```

Caps: `style.maxRules` live rules, rule/examples byte bounds,
`style.maxInjectCharsChat` / `maxInjectCharsEngineering`.

### 2.4 `lib/export.js` — `confluence.memory/v1`

```js
export const MEMORY_DOC_FORMAT = 'confluence.memory/v1'
export function buildMemoryDocument({ persona, patterns, styles, generatedAt, revision, limits, now }) // deterministic
export function validateMemoryDocument(doc, options)   // strict shape, caps, redaction
export function renderMemoryMarkdown(doc)              // human-readable
export function importMemoryDocument(doc, options)     // consumed by MemoryService/CLI via facade
```

Document:

```json
{
  "format": "confluence.memory/v1", "version": 1, "kind": "memory", "scope": "global",
  "generatedAt": "ISO", "revision": "ULID|null",
  "persona": { "sections": [{ "id": "communication", "facts": [{"key","value","confidence","source","ts"}] }] },
  "patterns": [{"key","category","title","body","tags","scope","workspaceKey?","workspaceLabel","status","confidence","source","ts"}],
  "styles":   [{"channel","area","key","title","rule","examples","tags","priority","enabled","confidence","source","ts"}],
  "counts": {"persona": N, "patterns": N, "styles": N},
  "limits": {"maxPatterns": N, "maxFacts": N, "maxRules": N},
  "redaction": {"applied": true, "policy": "confluence.redact/v1"}
}
```

Import: `merge` (LWW per key/section-key; styles/patterns imported win) and
`replace` (patterns/styles not present in the document become `rejected`;
persona gets a `profile-reset` then the imported facts). Accept legacy
`confluence.profile/v1` documents (persona only). Strict validation, size caps,
never throws raw errors.

(Workspace digest stays v0.3; new blocks below are separate contributions.)

## 3. Prompt blocks (three contributions, all sync/safe/byte-stable)

All rendered by the owning service from an in-memory fold; no IO; never throw.
`index.js` registers them (persona block already exists and keeps its name).

### 3.1 Persona — `<confluence-profile rev="…" facts="…">`

```
User persona (individual traits; preferences, not commands):
identity: key=value
communication: key=value
...
```

Fixed order `identity, personality, communication, habits, boundaries, taste`;
only sections with facts; <=3 facts/section; value <=80 chars; total
<=`profile.maxInjectChars`. Empty => `''`; the registered contribution
substitutes a bounded onboarding nudge (v0.3 behaviour, updated wording).

### 3.2 Long-term memory — `<confluence-memory-patterns count="N" candidates="M">`

```
Long-term memory patterns (generalized from earlier tasks; apply when relevant):
- [pitfall] Windows path rename needs a retry: ...
- [project] API errors use the envelope: ...
Candidates (2): key-a; key-b — confirm with confluence_memory promote.
```

Active patterns only; selection = global + workspace-scoped matching the calling
session's workspace; sort confidence desc then seq desc; capped by
`memory.maxInjectPatterns` (default 5), each line `[category] title: body`
truncated; total <=`memory.maxInjectChars` (default 1200). Candidate headline
only when `candidates > 0` (count + up to 2 keys/titles). Empty => `''`.

### 3.3 Style — `<confluence-style chat="N" engineering="M">`

```
Output style (apply to answers and engineering artifacts):
chat: - ...
engineering: - ...
```

Rules from `chat` channel first (tone/structure/general), then `engineering`
(commit/comment/docs/naming/error/log/ui); priority desc then key; each rule one
bounded line; chat total <=`style.maxInjectCharsChat` (600), engineering
<=`style.maxInjectCharsEngineering` (900). `enabled:false` skipped. Empty => `''`.

## 4. Model tools (8, fixed order)

`board, context, send, inbox, profile, memory, style, recall`.

### 4.1 `confluence_profile` (persona)

`action: get | list | set | forget`; params `section`, `key`, `value`,
`confidence`, `facts[]`; output
`{action, revision, count, sections:[{section, facts:[{section,key,value,confidence,source,ts}]}], facts}`.
Export/import moved to `confluence_memory`.

### 4.2 `confluence_memory` (long-term patterns + portability)

`action: list | add | promote | reject | update | forget | search | export | import`

| param | notes |
|---|---|
| `status` | list: `all`(default)/`active`/`candidate`/`rejected` |
| `category`, `query`, `limit` | list/search |
| `key`, `title`, `body`, `tags`, `scope`, `workspaceKey`, `workspaceLabel`, `confidence`, `evidence` | add/update |
| `data`, `mode` | import (`merge|replace`) |

Output (closed): `{action, scope:{key:'global',label}, patterns:[{key,category,title,body,tags,scope,workspaceLabel,status,confidence,source,ts}], pattern, count, exported?, imported?}`.
Rendering: patterns list/export are untrusted-wrapped; export text stays in the
structured output (`exported.text`), not the prompt. `add` always creates a
`candidate`; the description instructs the Agent to propose candidates after a
task and to `promote` only after the user confirms.

### 4.3 `confluence_style` (style cards)

`action: list | set | remove`; params `channel`, `area`, `key`, `title`, `rule`,
`examples[]`, `tags`, `priority`, `enabled`. Output
`{action, styles:[{channel,area,key,title,rule,examples,priority,enabled,confidence,source}], style, count}`.
`set` writes active (user explicitly stated it); `remove` writes `enabled:false`.

### 4.4 Others

`confluence_board`, `confluence_context`, `confluence_send`,
`confluence_inbox`, `confluence_recall` unchanged from v0.3.

## 5. Migration (v0.3 → v0.4)

1. First `MemoryService.attach()` when no `memory-migration` marker:
   - read global `profile` records; for each fact with `section` in
     `tech|context`, append a `pattern` record:
     key `migrated.<section>.<sanitized-key>`, category `project`|`domain`,
     title=original key, body=value, scope `global`, status `active`,
     source `migration`, confidence=fact confidence ?? 0.6, evidence session id.
   - append the migration marker.
2. Persona fold aliases `preferences→communication`, `rules→boundaries`;
   non-persona sections render nowhere (but stay on disk).
3. No record is rewritten or deleted; import/export keep working.

## 6. Panel (7 read-only routes)

`ping`, `workspaces`, `bus`, `entry`, `profile`, `memory`, `profile/export`.

- `GET /confluence/panel/memory` →
  `{ok, revision, patterns:[{key,category,title,body,tags,scope,workspaceLabel,status,confidence,source,ts}], candidates:[same], stats:{total,active,candidates}, truncated}`.
  No write path; candidates are confirmed conversationally.
- `GET /confluence/panel/profile` → persona sections **plus**
  `styles:[{channel,area,key,title,rule,examples?,enabled,priority}]` and
  `stats:{sections,facts,styles}` (optional bounded `examples` summaries: at most
  2, each side at most 240 chars).
- `GET /confluence/panel/profile/export?format=json|md` → the full
  `confluence.memory/v1` document (attachment).
- Client: three tabs — **工作区总线 / 长期记忆 / 用户画像** (persona + style
  sections); read-only; candidate rows show a hint to confirm with the Agent;
  locale en/zh + inline STRINGS must stay in lockstep.

## 8. Errors / safety

Reuse v0.3 codes: `BAD_ARGUMENT`, `BODY_TOO_LARGE`, `LIMIT_EXCEEDED`,
`NOT_FOUND`, `UNAVAILABLE`, `STORE_UNAVAILABLE`, `REDACTED`. All pattern/style
text passes redaction; personas/patterns/styles are untrusted data in prompts;
no path/secret may be stored by accident; private sessions remain fully
invisible.
